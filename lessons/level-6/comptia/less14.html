Lesson 14: Securing Applications

CompTIA CySA+ (CS0-004)

Overview

Finding application flaws is half the job; preventing them is the other half. This lesson covers secure coding practices and the testing that keeps applications safe from design to production.

You will learn:

  • secure coding practices that prevent the common vulnerabilities;
  • static and dynamic application security testing (SAST and DAST);
  • software composition analysis, software bills of materials and supply chain risk;
  • measuring a program with the Software Assurance Maturity Model (SAMM).

On the exam this is mostly objectives 2.3 (mitigation: secure coding) and 2.4 (application security and third-party risk).

Step 2: Key ideas to remember

Secure coding: the fix for each flaw

PracticePrevents
Parameterized queries (prepared statements)SQL injection
Input validation (allow lists) and output encodingCross-site scripting and other injection
Server-side access checks on every requestBroken access control
Anti-CSRF tokens and SameSite cookiesCross-site request forgery
Secrets kept out of code (use a vault)Leaked keys and passwords
Generic error messages; detailed errors only in logsInformation disclosure
Least privilege for the application's own accountsLimits the damage of any flaw

Testing throughout the life cycle

  • SAST (static) reads the source code without running it. It finds problems early, in the developer's pipeline, but can raise false positives.
  • DAST (dynamic) attacks the running application from outside, as an attacker would. It finds real, exploitable issues but only later, once the app runs.
  • SCA (software composition analysis) lists the open-source libraries an app uses and flags known-vulnerable versions.
  • An SBOM (software bill of materials) is the full ingredient list. When a library flaw like Log4Shell is announced, the SBOM tells you in minutes which applications are affected.
  • SAMM, the OWASP Software Assurance Maturity Model, measures how mature a software security program is and what to improve next.

When code can't be fixed quickly, a web application firewall (WAF) is a common compensating control.

Check your understanding

What is the most effective fix for SQL injection?

Parameterized queries keep user input as data, so it can never change the query. Hiding errors only makes the flaw harder to find.

A critical flaw is announced in a popular open-source logging library. What tells you fastest which of your applications use it?

An SBOM lists every component in each application, so you can search it immediately. SCA tools keep it current.

Which testing method examines source code without running the application?

Static analysis reads code; dynamic analysis tests the running application.
