Lesson 5: Applying Access Management

CompTIA CySA+ (CS0-004)

Overview

Most attacks today start with a stolen identity rather than a hacked server. This lesson covers how access is granted and protected, and the signs that an account has been taken over.

You will learn:

  • authentication and authorization methods, including MFA and single sign-on;
  • privileged access management (PAM) and secrets management;
  • identity-based indicators of compromise such as impossible travel.

On the exam this is mostly objectives 1.1 (identity and access management) and 1.2 (identity-based indicators).

Step 3: Key ideas to remember

Who are you, and what may you do?

  • Authentication proves who you are (password, passkey, MFA). Authorization decides what you may do once signed in (roles, permissions).
  • MFA adds a second factor. Phishing-resistant methods (passkeys, FIDO2 security keys) are stronger than codes or push prompts.
  • Single sign-on and federation (SAML, OAuth, OpenID Connect) let one identity provider vouch for the user to many apps. It is convenient, and it makes that one account very valuable to attackers.

Protecting the most powerful accounts

  • Privileged access management (PAM) keeps admin credentials in a vault, hands them out just in time for a set period, records admin sessions, and rotates the passwords afterwards.
  • Secrets management: API keys, tokens and service passwords belong in a secrets vault, never in code or configuration files. A key pushed to a public code repository can be found and abused within minutes.

Signs an identity has been compromised

IndicatorWhat it looks like
Impossible travelSign-ins from two places too far apart for the time between them
MFA fatigueDozens of push prompts until a tired user taps "approve"
Password sprayingOne common password tried against many accounts, a few failures each
Unauthorized accessAn account suddenly reading data or using admin tools it never touched before
Persistence changesA new MFA device, mail-forwarding rule or app consent added right after a risky sign-in

Check your understanding

A user signs in from Denver at 9:00 and from Singapore at 9:20. What is this indicator called?

No one can travel that far in 20 minutes, so at least one sign-in is not the real user (or is a VPN that needs checking).

A developer pushed code containing a cloud API key to a public repository. What should happen first?

Assume the key is already copied. Revoke it so it stops working, then check the logs for misuse and store the new key in a vault.

Which control hands out admin credentials only when needed, for a limited time, and records the session?

PAM vaults privileged credentials, grants them just in time, records use and rotates them afterwards.
