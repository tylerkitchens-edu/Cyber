Overview

Before you can spot something wrong on a computer, you need to know what right looks like. This lesson covers how systems are hardened, which files and processes matter, and how endpoints and mobile devices are kept to a standard.

You will learn:

  • system hardening and secure configuration baselines;
  • the critical files on Windows and Linux that attackers go after;
  • what normal system processes look like, so you can spot impostors;
  • how endpoint and mobile device management keep devices compliant.

On the exam this is mostly objective 1.1 (operating system and device management concepts).

Step 3: Key ideas to remember

Hardening

Hardening means reducing what an attacker can use. Typical steps: remove or disable software and services you don't need, close unused ports, change default accounts and passwords, apply patches, turn on logging, and restrict administrator rights. A configuration baseline (for example a CIS Benchmark) writes the hardened settings down so every system can be built and checked against it.

Normal processes, and impostors

Windows always runs certain processes, such as svchost.exe, lsass.exe and services.exe, from C:\Windows\System32. Malware often hides behind those names. Warning signs: the right name in the wrong folder, a near-miss spelling (scvhost.exe), an unexpected parent process, or a second copy of a process that should only run once (lsass.exe).

Endpoints and mobile devices

Endpoint management tools push the baseline, patches and security software to every computer. Mobile device management (MDM) does the same for phones and tablets: it enforces a screen lock and encryption, separates work data from personal data, and can wipe a lost device.

Check your understanding

EDR reports svchost.exe running from C:\Users\Public\. What should you think?

Many copies of svchost.exe are normal, but only from System32. The right name in the wrong folder is a classic way malware hides.

Which Linux file holds the password hashes?

/etc/passwd lists accounts but is readable by everyone; the hashes moved to /etc/shadow, which only root can read.

Which of these is a hardening step?

Hardening removes what an attacker could use. The other three all make the system easier to attack.
