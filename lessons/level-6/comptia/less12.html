Overview

A good SOC gets faster and more consistent over time. This lesson covers standardising work, automating the repetitive parts, tuning detections and connecting tools together.

  • standard processes: team coordination, playbooks and runbooks;
  • automation and orchestration with SOAR, and infrastructure as code;
  • data enrichment, rule and alert tuning, and dashboards;
  • connecting tools with APIs, webhooks and plug-ins, and governing the use of AI.

On the exam this is mostly objectives 1.5 (efficiency and process improvement) and 1.6 (AI in security operations).

Step 3: Key ideas to remember

What to automate

Automate work that is repetitive, well defined and low risk: enriching an alert with reputation and asset data, opening and updating tickets, blocking a confirmed-bad indicator, resetting a password after confirmed phishing. Keep people on judgement calls and on actions that could cause an outage.

A SOAR playbook, step by step (reported phishing)

  1. A user reports an email; the SOAR platform opens a ticket.
  2. It extracts the sender, links and attachment hashes.
  3. It checks each against threat intelligence and a sandbox.
  4. If malicious: block the sender and links, remove the same email from every mailbox, and alert an analyst. If clean: reply to the user and close the ticket.

Keeping detections useful

  • Rule and alert tuning cuts false positives (exclude a known-good scanner, adjust a threshold) so real alerts aren't buried. Track the false-positive rate before and after.
  • Dashboards show volume, trends and open work at a glance.
  • Infrastructure as code (IaC) builds systems from version-controlled templates, so every build is identical and changes are reviewed.

Connecting tools

  • API: one tool asks another for data or to take an action, when it chooses to.
  • Webhook: a tool pushes a message to a set address the moment an event happens.
  • Plug-in: a ready-made add-on that connects a product to a platform.

Check your understanding

Which task is the best first candidate for automation?

Enrichment is repetitive, well defined and safe to automate. The others need human judgement and authority.

A detection fires 500 times a day, almost all on a known-good backup server. What should the team do?

Tuning keeps the detection for real threats while removing known noise. Deleting the rule or the logs creates blind spots.

Which describes a webhook?

Webhooks push on an event. With an API call, the calling tool decides when to ask.
