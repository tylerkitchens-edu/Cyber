Lesson 1: Identifying Security Operations Fundamentals

CompTIA CySA+ (CS0-004)

Overview

Level 6 prepares you for CompTIA CySA+, the analyst certification. Security+ taught you to recognise threats and controls. CySA+ asks you to work like an analyst: read logs and alerts, decide what is real, and act on it.

This first lesson sets up how a security operations center (SOC) works. A SOC is the team that watches an organization's systems around the clock. You will learn:

  • how an event on a computer becomes a log, and how logs become the alerts analysts work on;
  • what makes logging trustworthy: collecting the right sources, synchronized clocks, protecting logs from tampering, and keeping them long enough;
  • who does what in a SOC, and how playbooks, automation and tuning keep the team consistent and efficient.

On the exam this is mostly objective 1.1 (system and network architecture in security operations: logging) and 1.5 (efficiency and process improvement).

Step 3: Key ideas to remember

From event to alert

Something happens (a sign-in, a program starting, a file download). The system logs it. The logs are sent to a central tool, usually a SIEM (security information and event management). The SIEM's rules raise an alert when something looks suspicious. Analysts work the alerts, not millions of raw logs, so an alert is only as good as the logs behind it.

What makes logging trustworthy

Logging conceptWhat it meansWhat goes wrong without it
IngestionEvery important source actually sends its logs to the SIEM.A server that never sends logs is a blind spot; an attack there raises no alert.
ConfigurationSystems are set to record the events that matter (sign-ins, new processes, permission changes).Default settings often skip the events an investigation needs.
Integrity and securityLogs are copied off the machine as they are written, and access to them is restricted.An attacker with admin rights clears the local log and the evidence is gone.
Time synchronizationEvery device sets its clock from the same time source (NTP).Events from two devices can't be put in the right order, so the timeline of an attack is wrong.
RetentionLogs are kept long enough, often set by law or contract.Many breaches are found months later; if the logs are gone, so is the story.

Who does what, and how the team stays consistent

  • Level 1 analysts triage alerts: real or false alarm? They close false alarms and escalate real threats.
  • Level 2 analysts investigate escalated alerts in depth and lead the response.
  • SOC engineers build and tune the tools, rules and integrations; the SOC manager tracks speed and quality.
  • Playbooks and runbooks write down how to handle each type of alert, so every analyst handles it the same way. A playbook sets out the overall response and its decision points; a runbook gives the detailed technical steps, which can often be automated.
  • Automation and tuning (for example SOAR, security orchestration, automation and response) add context to alerts automatically and cut false alarms, so analysts spend their time on real threats.

Check your understanding

The firewall logged a connection at 14:02. The web server logged the same connection at 14:09. Which logging concept has failed?

The two clocks disagree by seven minutes, so events can't be lined up into one timeline. Every device should set its time from the same source (NTP).

An attacker gained admin rights on a server and cleared its Security event log. What would have kept the evidence?

Copies already sent off the machine survive even if the local log is wiped. That is the "integrity and security" part of logging. Clearing the log is itself a warning sign: Windows records it as event 1102.

Two analysts handle the same "phishing email reported" alert in completely different ways. What would fix this?

Standardizing the process with a playbook makes every analyst take the same steps and decisions. Escalating everything just moves the problem and overloads Level 2.

What is a Level 1 SOC analyst's main job when a new alert arrives?

Level 1 is triage. Deeper investigation and remediation go to Level 2, and rule-writing belongs to SOC engineering.
