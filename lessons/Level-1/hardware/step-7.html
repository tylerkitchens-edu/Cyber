Cloud Computing

Lesson

Learning Objectives

  • Explain what virtualization and a hypervisor are, and tell a Type 1 hypervisor from a Type 2.
  • List what a computer needs to run virtual machines.
  • Give reasons to use virtualization on a desktop, and tell virtual machines from containers.
  • Tell the cloud deployment models apart: public, private, hybrid and community.
  • Tell IaaS, PaaS and SaaS apart, and say who manages what in each.
  • Describe the cloud characteristics the A+ exam names.

Virtualization

Virtualization uses software to split one physical computer into several isolated virtual machines (VMs). Each VM behaves like a complete computer with its own operating system, called the guest, while sharing the real hardware of the host. For example, a Windows laptop can run a Linux VM in a window next to its normal apps.

A VM is stored as a few files: a settings file (how many CPU cores, how much memory) and a virtual disk file that holds the guest's operating system and data. Because it is just files, a VM can be copied, backed up, moved to another host, or rolled back with a snapshot.

Hypervisors

The hypervisor (also called a virtual machine manager) is the software that creates and runs VMs and shares the hardware between them.

  • Type 1 (bare metal): runs directly on the hardware, with no operating system underneath. Used on servers and in data centers because it is efficient and stable. Examples: VMware ESXi, Microsoft Hyper-V, Proxmox VE.
  • Type 2 (hosted): an app that runs on top of a normal operating system. Easy to install on a desktop or laptop; a little slower because the host OS sits in between. Examples: Oracle VirtualBox, VMware Workstation, Parallels Desktop.

What a host needs

Every running VM takes a share of the host's real resources, so plan for the host plus every VM you will run at the same time.

  • CPU with virtualization support: Intel VT-x or AMD-V, switched on in the BIOS/UEFI settings (often off from the factory; see the Boot Process lesson). Without it, most hypervisors will not start a VM. More cores let you give each VM its own.
  • Memory (RAM): usually the first limit. Each VM's RAM is reserved while it runs, on top of what the host needs.
  • Storage: free space for each virtual disk and its snapshots. An SSD makes VMs far faster.
  • Network: each VM gets a virtual network card. Common modes: NAT (the VM shares the host's address and reaches the Internet, but the network cannot see it), bridged (the VM joins your real network like another device) and host-only / internal (the VM can talk only to the host or other VMs, useful for testing malware or attacks safely).
  • Security: a guest is a full computer. It needs its own updates, antivirus and passwords, even though it runs inside another one.

A student installs VirtualBox, but every 64-bit VM fails to start with a message that "VT-x is disabled". The laptop has 16 GB of RAM and plenty of free space. What should they do?

VT-x (or AMD-V on AMD processors) is a CPU feature the hypervisor needs. It is switched on in the firmware settings, not in Windows.

Why use virtualization on a desktop?

  • Sandbox: open a suspicious file or website in a VM, then throw the VM away (or roll back a snapshot). Anything it infects stays inside.
  • Test and development: try an update, a new app or a configuration change on a copy before touching a real machine.
  • Legacy software and operating systems: keep an old program running on the older operating system it needs.
  • Cross-platform: run Linux tools on a Windows laptop, or test a website on another operating system.

Containers are a lighter alternative. A container packages one app with the libraries it needs, but shares the host's operating system kernel instead of running a whole guest OS. Containers start in seconds and use little memory; a VM gives stronger isolation and can run a different operating system. Docker is the best-known container tool.

Desktop virtualization (VDI) runs users' desktops as VMs on servers in a data center or the cloud. People connect from a laptop or thin client, and IT manages every desktop in one place.

A help-desk technician receives an email attachment that might be malware and must find out what it does without risking the office network. What is the best approach?

A VM is a sandbox: host-only networking keeps the file off the real network, and the snapshot erases whatever it did.

Cloud Computing

Cloud computing means renting computing resources (servers, storage, databases, apps) from a provider over the Internet instead of buying and running them yourself. The provider runs huge numbers of virtualized servers and hands out shares of them on demand. Virtualization is what makes the cloud possible.

Deployment models: who uses it

  • Public cloud: shared by many customers and run by a provider such as AWS, Microsoft Azure or Google Cloud.
  • Private cloud: used by one organization only. It can run in the organization's own data center or be hosted by a provider just for them. More control, higher cost.
  • Hybrid cloud: a mix of public and private, connected together. For example, sensitive records stay in the private cloud while the public website runs in the public cloud.
  • Community cloud: shared by several organizations with the same needs, such as government agencies or hospitals with the same compliance rules.

Service models: what you rent

  • Infrastructure as a Service (IaaS): virtual machines, storage and networks. You install and manage the operating system and everything above it. Examples: Amazon EC2, Azure Virtual Machines.
  • Platform as a Service (PaaS): a ready platform to run your own code. The provider manages the servers and operating system; you manage your app and its data. Examples: Heroku, Google App Engine, Azure App Service.
  • Software as a Service (SaaS): a finished app used through a browser or app. The provider manages everything; you manage your users, settings and data. Examples: Microsoft 365, Gmail, Salesforce, Zoom.

Many cloud breaches come from customer mistakes, such as a storage bucket left open to the public or an account without multifactor authentication.

A company rents virtual servers from a cloud provider and installs Windows Server and its own web app on them. Which service model is this, and who must install the Windows security updates?

Renting virtual machines is IaaS. In IaaS the customer manages the operating system, so patching Windows is the company's job.

Cloud characteristics

The A+ exam expects you to recognize these terms:

  • Shared resources: many customers use the same pool of hardware. Internal shared resources belong to your organization; external ones belong to a provider.
  • Multitenancy: many customers ("tenants") run on the same hardware, kept separate from each other by software.
  • Metered utilization: you pay for what you use, by the hour, the gigabyte or the user, like an electricity bill.
  • Rapid elasticity: resources grow automatically when demand rises and shrink when it falls.
  • High availability: the service keeps running when hardware fails, because it is copied across servers and often across data centers.
  • File synchronization: files saved to services like OneDrive, Google Drive or Dropbox are kept the same on every device.

An online store's website automatically adds servers during a Black Friday rush and removes them the next week, and the store only pays for the extra hours. Which two characteristics is it using?

Growing and shrinking with demand is rapid elasticity; paying only for the hours used is metered utilization.

Benefits and drawbacks

  • Benefits: no hardware to buy up front; scale up or down quickly; work from anywhere and collaborate easily; providers offer backups and copies in several locations.
  • Drawbacks: everything depends on the Internet connection and on the provider staying up; monthly costs can grow quietly; moving away from one provider can be hard (lock-in); your data sits on someone else's hardware, so contracts, location and compliance rules matter.

Most SaaS apps are paid by subscription: each user needs a licence, paid monthly or yearly, and access stops when the payments stop. This is different from older software bought once and installed on each computer.

Try it on your computer (Windows, 3 minutes)

  1. Press Ctrl+Shift+Esc to open Task Manager, go to Performance > CPU, and find Virtualization under the graph. Is it Enabled? If it says Disabled, this is the setting you would switch on in the BIOS/UEFI before running VMs.
  2. Note the number of Cores and, under Memory, the total RAM. How many VMs with 2 cores and 4 GB of RAM each could this computer run while you still use it?
  3. Optional: open Command Prompt, type systeminfo and press Enter. The last lines show the Hyper-V Requirements, or "A hypervisor has been detected" if a hypervisor is already running.
