Routing Fundamentals & NAT

Level 3: Networking

Learning Objectives

  • Explain how routers make forwarding decisions using routing tables.
  • Differentiate between static and dynamic routing and identify when each is appropriate.
  • Describe common dynamic routing protocols and their use cases in enterprise environments.
  • Explain the purpose of default gateways and their role in inter-network communication.
  • Describe Network Address Translation (NAT) and Port Address Translation (PAT) and explain why they are essential to modern networking.
  • Use traceroute to analyze the path packets take across a network and identify potential points of failure.

How Routing Works

In earlier lessons, you learned that routers connect different networks together. But how does a router actually decide where to send a packet? The answer lies in the routing table — a data structure stored in the router's memory that maps destination networks to the next hop or outgoing interface the packet should be forwarded through.

When a packet arrives at a router, the router examines the destination IP address in the packet header. It then compares that address against entries in its routing table using a process called longest prefix match — the most specific route that matches the destination wins. If no specific match is found, the router falls back to a default route (0.0.0.0/0), which typically points toward the Internet or a core router.

The Default Gateway

Every device on a network that needs to communicate outside its local subnet must have a default gateway configured. The default gateway is simply the IP address of the router interface on the local network. When a device wants to send data to an IP address that isn't on its own subnet, it forwards the packet to the default gateway, which then routes it toward the destination.

For example, if your computer has the IP address 192.168.1.50/24 and needs to reach 10.0.0.25, it recognizes that 10.0.0.25 is not on the 192.168.1.0/24 network. It sends the packet to its default gateway (e.g., 192.168.1.1), and the router handles it from there.

Routing Table Components

A typical routing table entry includes:

  • Destination Network: The network address and prefix length (e.g., 10.0.0.0/8).
  • Next Hop: The IP address of the next router in the path toward the destination.
  • Outgoing Interface: The physical or logical interface the packet should be sent out of.
  • Metric / Cost: A value used to determine the "best" path when multiple routes exist to the same destination. Lower metrics are preferred.
  • Route Source: How the route was learned — directly connected, statically configured, or dynamically discovered.

Static vs. Dynamic Routing

Routes can be added to a routing table in two fundamental ways: manually (static) or automatically (dynamic).

Static Routing

A static route is manually configured by a network administrator. The administrator explicitly tells the router: "To reach network X, forward packets to next-hop Y." Static routes are simple, predictable, and require no additional protocol overhead. They are ideal for small networks, stub networks (networks with only one exit path), or specific paths that should never change.

The downside is scalability and resilience. If a link goes down, static routes don't automatically adjust — an administrator must manually update the configuration. In a large enterprise network with hundreds of subnets, maintaining static routes becomes impractical.

Dynamic Routing

Dynamic routing uses routing protocols that allow routers to automatically discover networks, share route information with neighboring routers, and adapt to topology changes. If a link fails, dynamic routing protocols detect the change and recalculate the best available path — often within seconds.

Common Dynamic Routing Protocols

You don't need to configure these protocols at this stage, but understanding what they do and where they're used is important for security analysis. When reviewing network logs or SIEM alerts, you may encounter references to these protocols.

  • RIP (Routing Information Protocol): One of the oldest routing protocols. Uses hop count as its metric (maximum of 15 hops). Simple but limited in scale. Rarely used in modern enterprise networks but still appears in legacy environments.
  • OSPF (Open Shortest Path First): A link-state protocol widely used in enterprise networks. Routers build a complete map of the network topology and calculate the shortest path using Dijkstra's algorithm. OSPF converges quickly after topology changes and scales well with proper area design.
  • BGP (Border Gateway Protocol): The protocol that runs the Internet. BGP is used between autonomous systems (large networks operated by ISPs, enterprises, or governments) to exchange routing information. Understanding BGP at a conceptual level helps explain how Internet traffic flows — and how BGP hijacking attacks can redirect traffic maliciously.

Why This Matters for Cybersecurity

Routing protocols can be targeted by attackers. Route poisoning, BGP hijacking, and rogue DHCP/gateway attacks all exploit how devices make routing decisions. As a security analyst, understanding routing fundamentals helps you recognize when traffic is taking an unexpected path — a potential indicator of compromise.

Network Address Translation (NAT)

Network Address Translation (NAT) is a process performed by routers and firewalls that modifies the source or destination IP address in packet headers as they pass through the device. NAT was originally developed to address IPv4 address exhaustion — there are only about 4.3 billion IPv4 addresses, far fewer than the number of devices connected to the Internet today.

How NAT Works

In a typical home or office network, devices use private IP addresses (e.g., 192.168.1.x, 10.0.0.x, 172.16.x.x) that are not routable on the public Internet. When a device sends traffic to the Internet, the router performing NAT replaces the private source IP with the router's public IP address before forwarding the packet. When the response comes back, the router translates the public address back to the original private address and delivers the packet to the correct internal device.

Types of NAT

  • Static NAT: Maps one private IP address to one public IP address permanently. Used when an internal server (e.g., a web server) needs to be consistently reachable from the Internet.
  • Dynamic NAT: Maps private addresses to a pool of available public addresses on a first-come, first-served basis. Less common today due to the prevalence of PAT.
  • PAT (Port Address Translation): Also called NAT overload. Maps many private IP addresses to a single public IP address by using unique port numbers to track each session. PAT is what most home routers and enterprise firewalls use. When you see your router's single public IP handling traffic from dozens of internal devices simultaneously, that's PAT in action.

NAT and Security

NAT provides a degree of obscurity by hiding internal IP addresses from external networks. However, NAT is not a security control — it was designed for address conservation, not protection. Attackers can still exploit services exposed through port forwarding, and NAT does nothing to prevent outbound malicious traffic from internal compromised hosts. Security should always be enforced through firewalls, ACLs, and proper segmentation — not relied upon through NAT alone.

Traceroute: Analyzing Network Paths

Traceroute (called tracert on Windows and traceroute on Linux/Mac) is a diagnostic tool that maps the path a packet takes from your device to a destination, showing every router (hop) along the way. It works by sending packets with incrementally increasing TTL (Time to Live) values — each router that processes the packet decrements the TTL by one, and when it reaches zero, the router sends back an ICMP "Time Exceeded" message, revealing its IP address.

Reading Traceroute Output

Each line in the traceroute output represents one hop. The output typically shows:

  • Hop number: The sequential position in the path.
  • Router IP address (or hostname): The identity of the device at that hop.
  • Round-trip times: Usually three time measurements (in milliseconds) showing how long it took to receive the response from that hop.

A sudden spike in latency at a specific hop may indicate congestion or a problem at that point in the network. Asterisks (* * *) in the output indicate that a hop did not respond — this could mean the router is configured to block ICMP traffic (common for security), not necessarily that there's a failure.

Traceroute for Security Analysis

Security analysts use traceroute to verify that traffic is taking expected paths, identify unexpected routing changes that could indicate a man-in-the-middle attack or BGP hijack, and troubleshoot connectivity issues to monitored assets. Comparing current traceroute output against a known baseline can quickly reveal anomalies.

Summary

  • Routers use routing tables to make forwarding decisions based on destination IP addresses.
  • Static routes are manually configured and best for simple or predictable paths. Dynamic routing protocols (RIP, OSPF, BGP) enable routers to adapt automatically to network changes.
  • NAT translates private IP addresses to public addresses, with PAT being the most common form used today.
  • NAT provides address conservation but is not a substitute for proper security controls.
  • Traceroute is a valuable diagnostic and security analysis tool for mapping network paths and detecting anomalies.
