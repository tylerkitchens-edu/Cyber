Network Services for Security Operations

Level 3: Networking

Learning Objectives

  • Explain how DNS, DHCP, SNMP, SMTP, and syslog function in an enterprise network environment.
  • Describe how each network service generates logs and telemetry relevant to security monitoring.
  • Identify indicators of compromise (IoCs) and suspicious activity within DNS, DHCP, and email logs.
  • Explain the role of syslog in centralized log collection and SIEM integration.
  • Recognize how attackers abuse common network services to conduct reconnaissance, exfiltrate data, or maintain persistence.

Why Network Services Matter for Security

In earlier coursework, you learned what services like DNS and DHCP do — DNS translates domain names to IP addresses, and DHCP automatically assigns IP addresses to devices. In this lesson, we shift focus from what they are to how security analysts use them.

Every network service generates data. That data — in the form of logs, queries, and traffic patterns — provides critical visibility into what's happening on a network. Security Operations Center (SOC) analysts and incident responders rely on these data sources daily to detect threats, investigate incidents, and validate that systems are functioning as expected.

DNS in Security Operations

The Domain Name System (DNS) is one of the most valuable data sources for security monitoring. Nearly every network action — browsing a website, downloading malware, communicating with a command-and-control (C2) server — begins with a DNS query. Because of this, DNS logs provide a comprehensive record of what domains devices on your network are trying to reach.

What DNS Logs Reveal

  • Query records: Which internal device requested which domain name, and when.
  • Response records: What IP address was returned, and whether the query was successful (NOERROR) or failed (NXDOMAIN — domain doesn't exist).
  • Record types: The type of DNS record requested (A, AAAA, MX, TXT, CNAME, etc.). Unusual record type requests can indicate suspicious activity.

DNS-Based Threats

  • DNS Tunneling: Attackers encode data within DNS queries and responses to exfiltrate information or communicate with C2 infrastructure. This works because DNS traffic is rarely blocked by firewalls. Indicators include unusually long subdomain strings, high query volume to a single domain, and TXT record queries to unfamiliar domains.
  • Domain Generation Algorithms (DGAs): Malware uses algorithms to generate hundreds of random-looking domain names (e.g., xj7kq9m2.net) and queries them in sequence, looking for the one the attacker has registered. High volumes of NXDOMAIN responses from a single host can indicate DGA activity.
  • DNS Spoofing / Cache Poisoning: An attacker injects forged DNS responses to redirect users to malicious sites. This can be detected by monitoring for unexpected changes in DNS resolution for known domains.

Key DNS Record Types for Analysts

  • A / AAAA: Maps a domain to an IPv4 or IPv6 address. The most common query type.
  • MX: Identifies the mail servers responsible for a domain. Used in email delivery.
  • TXT: Stores arbitrary text data. Commonly used for SPF, DKIM, and DMARC email authentication records — but also abused for DNS tunneling.
  • CNAME: An alias that points one domain name to another. Used for CDN configurations and load balancing.
  • PTR: Reverse DNS — maps an IP address back to a domain name. Useful for verifying the identity of mail servers and investigating suspicious IPs.

DHCP in Security Operations

The Dynamic Host Configuration Protocol (DHCP) automates IP address assignment on a network. When a device connects, it sends a DHCP Discover broadcast, receives an Offer from the DHCP server, sends a Request to accept, and receives an Acknowledgment — the four-step process known as DORA (Discover, Offer, Request, Acknowledge).

What DHCP Logs Reveal

  • Lease records: Which IP address was assigned to which MAC address, and when. This is essential for correlating network activity to specific physical devices during investigations.
  • Lease duration and renewals: How long a device has been connected and whether it's actively renewing its lease.
  • Hostname information: Many DHCP clients send their hostname during the request, which can help identify the device type or owner.

DHCP-Based Threats

  • Rogue DHCP Servers: An attacker sets up an unauthorized DHCP server on the network that hands out malicious configurations — such as pointing devices to a fake DNS server or a gateway controlled by the attacker. This enables man-in-the-middle attacks. Detection involves monitoring for DHCP Offer packets from unexpected source IP or MAC addresses.
  • DHCP Starvation: An attacker floods the DHCP server with requests using spoofed MAC addresses, exhausting the available IP address pool and causing a denial of service for legitimate devices.
  • MAC-to-IP Correlation: During incident response, DHCP logs are critical for answering the question: "Which physical device had IP address X.X.X.X at this specific time?" Without DHCP logs, attributing network activity to a specific device becomes extremely difficult.

SNMP: Network Monitoring

The Simple Network Management Protocol (SNMP) is used to monitor and manage network devices — routers, switches, firewalls, servers, and printers. SNMP operates on a manager-agent model: a central SNMP manager (often part of a network monitoring platform) queries SNMP agents running on managed devices to collect performance data.

Key SNMP Concepts

  • OID (Object Identifier): A unique identifier for each piece of data an SNMP agent can report — such as CPU utilization, interface status, or bandwidth usage.
  • MIB (Management Information Base): A structured database that defines what OIDs are available on a device. Think of it as a dictionary that translates OID numbers into human-readable descriptions.
  • SNMP Traps: Unsolicited alerts sent from an agent to the manager when a predefined condition occurs — such as an interface going down, high CPU usage, or a failed login attempt. Traps are critical for real-time alerting.
  • Community Strings: Essentially passwords used in SNMP v1 and v2c to authenticate requests. These are sent in plaintext, making older SNMP versions a security risk. SNMP v3 adds encryption and proper authentication and should always be used in production environments.

SNMP Security Concerns

SNMP v1/v2c community strings (especially the common defaults "public" for read-only and "private" for read-write) are a well-known attack vector. An attacker who discovers the read-write community string can modify device configurations remotely. Always use SNMP v3 with authentication and encryption, and change default community strings immediately.

SMTP and Email Security

The Simple Mail Transfer Protocol (SMTP) is responsible for sending email between mail servers. Understanding email flow is important for security because email remains the most common attack vector for phishing, malware delivery, and business email compromise (BEC).

Email Authentication Records

Three DNS-based mechanisms help organizations prevent email spoofing and validate sender identity:

  • SPF (Sender Policy Framework): A DNS TXT record that specifies which mail servers are authorized to send email on behalf of a domain. Receiving servers check incoming mail against the SPF record to verify the sending server is legitimate.
  • DKIM (DomainKeys Identified Mail): Adds a cryptographic signature to outgoing emails. The receiving server verifies the signature using a public key published in DNS, confirming the message hasn't been tampered with in transit.
  • DMARC (Domain-based Message Authentication, Reporting, and Conformance): Builds on SPF and DKIM by defining a policy for how receiving servers should handle messages that fail authentication (quarantine, reject, or none). DMARC also provides reporting so domain owners can monitor abuse.

Email Header Analysis

When investigating suspicious emails, analysts examine the email headers — metadata that records the path the email took from sender to recipient, including originating IP addresses, mail server hostnames, authentication results (SPF pass/fail, DKIM verification), and timestamps. Headers are read from bottom to top, with the oldest entries at the bottom.

Syslog: Centralized Logging

Syslog is a standard protocol (UDP port 514, or TCP/TLS port 6514 for encrypted transport) used to send log messages from network devices, servers, and applications to a centralized log collector or SIEM platform. Centralized logging is foundational to security operations — without it, analysts would need to log into each device individually to review events.

Syslog Severity Levels

Syslog messages are classified by severity on a scale from 0 (most critical) to 7 (least critical):

  • 0 — Emergency: System is unusable.
  • 1 — Alert: Immediate action required.
  • 2 — Critical: Critical conditions (e.g., hardware failure).
  • 3 — Error: Error conditions.
  • 4 — Warning: Warning conditions that may require attention.
  • 5 — Notice: Normal but significant conditions.
  • 6 — Informational: General operational messages.
  • 7 — Debug: Detailed diagnostic information used during troubleshooting.

In a SIEM environment, syslog feeds from firewalls, routers, switches, and servers are aggregated, normalized, and correlated to detect patterns that no single log source would reveal on its own. For example, a firewall deny log combined with a DNS query to a known-malicious domain from the same source IP creates a high-confidence alert.

Summary

  • DNS logs are among the most valuable data sources for threat detection — monitor for tunneling, DGA activity, and cache poisoning.
  • DHCP logs provide critical MAC-to-IP correlation needed during incident investigations.
  • SNMP enables network monitoring through traps and polling — always use v3 with encryption in production.
  • Email security relies on SPF, DKIM, and DMARC to prevent spoofing. Header analysis is a core investigation skill.
  • Syslog centralizes logs from across the network into a SIEM for correlation and alerting.
  • Every network service is both a source of security telemetry and a potential attack surface — understanding both sides is essential.
