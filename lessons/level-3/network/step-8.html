Network Traffic Analysis & Monitoring

Level 3: Networking

Why Traffic Analysis Matters

Network traffic is the lifeblood of every organization — and it's also where attacks leave evidence. Malware beaconing to command-and-control servers, data exfiltration, lateral movement between compromised hosts, reconnaissance scanning — all of these generate detectable network traffic patterns.

As a cybersecurity analyst, your ability to capture, interpret, and act on network traffic data is one of the most valuable skills you can develop. This lesson introduces the tools and techniques you'll use to monitor networks and identify threats.

Packet Capture Fundamentals

A packet capture (PCAP) is a recording of raw network traffic — every packet, with full header and payload data, saved to a file for analysis. Packet captures provide the most granular visibility available, allowing analysts to reconstruct sessions, examine payloads, and see exactly what was transmitted.

How Packet Capture Works

To capture traffic, you need to position your capture point where it can see the relevant packets:

  • Network TAP (Test Access Point): A physical device installed inline on a network link that copies all traffic passing through it to a monitoring port. TAPs are passive and do not introduce latency or risk of failure. They are the gold standard for full-fidelity packet capture.
  • SPAN/Mirror Port: A switch feature that copies traffic from one or more ports (or VLANs) to a designated monitoring port. Easier to deploy than TAPs but may drop packets under heavy load since the switch prioritizes forwarding over mirroring.
  • Host-Based Capture: Running a capture tool (like Wireshark or tcpdump) directly on a device. This captures only traffic to and from that specific host. Useful for targeted analysis but provides limited network-wide visibility.

When to Use Packet Capture

Full packet capture is resource-intensive — storing every packet on a busy network generates enormous amounts of data. Analysts typically use full PCAP for targeted investigations: confirming an alert from a SIEM, reconstructing an attack timeline, analyzing malware communication patterns, or extracting transferred files. For continuous broad monitoring, flow data (discussed below) is more practical.

Wireshark: Practical Traffic Analysis

Wireshark is the most widely used network protocol analyzer. It captures live traffic and provides a graphical interface for inspecting packets at every layer of the network stack. You were briefly introduced to Wireshark in the A+ curriculum — this lesson expands on that foundation.

Wireshark Interface Overview

  • Packet List Pane (top): Displays a summary of each captured packet — time, source/destination IPs, protocol, and a brief info description.
  • Packet Details Pane (middle): Shows the full protocol breakdown for the selected packet, organized by network layer. You can expand each layer to see header fields.
  • Packet Bytes Pane (bottom): Displays the raw hex and ASCII representation of the packet data.

Essential Display Filters

Wireshark captures can contain thousands or millions of packets. Display filters let you focus on what matters. Some essential filters:

  • ip.addr == 192.168.1.50 — Show all traffic to or from a specific IP.
  • tcp.port == 443 — Show all HTTPS traffic.
  • dns — Show only DNS queries and responses.
  • http.request.method == "POST" — Show only HTTP POST requests (useful for finding form submissions or data uploads).
  • tcp.flags.syn == 1 && tcp.flags.ack == 0 — Show only TCP SYN packets (new connection attempts). A flood of these from one source could indicate a SYN scan or SYN flood attack.
  • frame contains "password" — Search packet content for a specific string. Useful for finding cleartext credential transmission.

Following Streams

One of Wireshark's most powerful features is the ability to follow a stream — right-click on any packet and select "Follow > TCP Stream" (or UDP/HTTP stream). This reconstructs the entire conversation between two endpoints in readable format, making it easy to see what data was exchanged. This is invaluable for analyzing C2 communications, data exfiltration, and suspicious file transfers.

Identifying Suspicious Traffic in Wireshark

Patterns to look for during analysis:

  • Beaconing: Regular, periodic connections from an internal host to an external IP — especially at consistent intervals (e.g., every 60 seconds). This pattern often indicates malware communicating with a C2 server.
  • Port scanning: A single source IP sending SYN packets to many different ports on the same destination (vertical scan) or the same port across many destinations (horizontal scan).
  • Unusual protocols or ports: SSH traffic on port 80, DNS traffic on non-standard ports, or encrypted traffic to unexpected destinations may indicate tunneling or evasion techniques.
  • Large data transfers to external IPs: Significant outbound data volume to unfamiliar destinations could indicate exfiltration.
  • Cleartext credentials: HTTP (not HTTPS), FTP, Telnet, and unencrypted SMTP can expose usernames and passwords in packet payloads.

NetFlow and sFlow: Traffic Metadata

While full packet capture provides maximum detail, it's not practical to store every packet on large networks indefinitely. NetFlow (developed by Cisco) and sFlow (an industry standard) collect traffic metadata — summary information about network sessions without capturing the actual packet contents.

What Flow Data Contains

A flow record typically includes:

  • Source and destination IP addresses
  • Source and destination port numbers
  • Protocol (TCP, UDP, ICMP)
  • Number of packets and bytes transferred
  • Start and end timestamps
  • TCP flags (SYN, ACK, FIN, RST)

This metadata is far smaller than full PCAP data and can be stored for weeks or months, enabling long-term trend analysis and historical investigation. Flow data is excellent for answering questions like: "What external IPs did this host communicate with over the past 30 days?" or "Which internal host transferred the most data to the Internet last week?"

Flow Data vs. PCAP: Complementary Tools

Think of flow data as the phone bill (who called whom, when, and for how long) and packet capture as the recorded phone call (the actual content of the conversation). Security teams typically use flow data for broad monitoring and trend detection, then pivot to full packet capture for deep-dive investigation when an alert fires.

Network Security Monitoring Tools

Beyond Wireshark, several specialized tools play critical roles in network security monitoring. Understanding what each tool does and where it fits in the security stack prepares you for the tooling you'll encounter in Security+ and CySA+ environments.

  • Nmap (Network Mapper): A network discovery and port scanning tool. Nmap identifies active hosts, open ports, running services, and operating system fingerprints on a network. Security teams use Nmap for asset discovery and vulnerability assessment. Attackers use it for reconnaissance — so understanding Nmap output helps you recognize scanning activity in your logs.
  • Snort: An open-source network intrusion detection and prevention system (IDS/IPS). Snort analyzes network traffic in real time against a database of rules (signatures) that describe known attack patterns. When a match is found, Snort generates an alert or blocks the traffic. Writing and tuning Snort rules is a key SOC analyst skill.
  • Zeek (formerly Bro): A network security monitoring platform that goes beyond signature matching. Zeek passively monitors traffic and generates detailed, structured logs describing network activity — connection logs, DNS queries, HTTP requests, file transfers, SSL/TLS certificate information, and more. Zeek's logs are highly valuable for threat hunting and forensic investigation because they provide rich context about network behavior.
  • tcpdump: A command-line packet capture tool available on Linux and macOS. Less visual than Wireshark but extremely useful for quick captures on servers and headless systems. Analysts often use tcpdump to capture traffic remotely, then transfer the PCAP file to Wireshark for detailed analysis.
  • NetSpot / Wi-Fi Analyzers: Tools for assessing wireless network performance, coverage, and interference. Useful for identifying rogue access points and verifying wireless security configurations.

Feeding Data into SIEM

All of the data sources discussed in this lesson — packet captures, flow data, IDS alerts, Zeek logs — can be forwarded to a Security Information and Event Management (SIEM) platform. The SIEM aggregates data from across the network, normalizes it into a common format, and applies correlation rules to detect complex attack patterns that no single data source would reveal.

For example, a SIEM might correlate a Snort IDS alert (suspicious inbound traffic) with Zeek connection logs (showing the targeted host subsequently made outbound connections to an unfamiliar IP) and DNS logs (showing queries to a recently registered domain) to generate a high-confidence alert for potential compromise.

You will work extensively with SIEM platforms in the Security+ and CySA+ portions of this program. The network monitoring skills you're building now provide the data that makes SIEM analysis possible.

Summary

  • Packet capture (PCAP) provides full visibility into network traffic and is essential for incident investigation and forensic analysis.
  • Wireshark is the primary tool for interactive traffic analysis — learn its display filters and stream-following capabilities.
  • NetFlow/sFlow collect traffic metadata for long-term monitoring and trend analysis, complementing full packet capture.
  • Nmap discovers hosts and services; Snort detects known threats via signatures; Zeek generates rich behavioral logs for hunting and forensics.
  • Network monitoring data feeds into SIEM platforms for centralized correlation, alerting, and investigation — connecting the dots across multiple data sources.
