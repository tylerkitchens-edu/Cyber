Overview

The Open Systems Interconnection (OSI) Model is a conceptual framework used to understand and implement network communications. It divides the communication process into seven distinct layers. This structured approach helps in troubleshooting, designing, and optimizing network systems. Each layer serves a unique function and communicates with adjacent layers to provide a complete communication pathway.

The seven layers include Application, Presentation, Session, Transport, Network, Data Link, and Physical Layer. These layers work together to facilitate data transmission across a network, allowing interoperability between different types of systems and technologies. Understanding each layer's role and function is key to troubleshooting and optimizing network performance.

Encapsulation: when a device sends, each layer from 7 down to 1 adds its own header (the transport layer adds ports, the network layer adds IP addresses, the data link layer adds MAC addresses and a CRC trailer). The receiving device works back up from 1 to 7, and each layer removes its header. A common memory aid from layer 1 up: "Please Do Not Throw Sausage Pizza Away".

Troubleshooting by layer: most technicians start at the bottom. Is the cable plugged in and the link light on (1)? Does the switch see the device (2)? Does it have a valid IP address and can it ping the gateway (3)? Is the port open and the service listening (4)? Only then look at the application (5-7).

Check your understanding

A switch reads a destination MAC address to decide which port to send data to. At which layer does it work, and what is the data called there?

MAC addresses belong to the data link layer (layer 2), where the data is a frame. Routers use IP addresses at layer 3, where it's a packet.

A user can ping a web server by its IP address, but the website won't load. Where should you look next?

A working ping proves layers 1-3 are fine. Check that port 443 (or 80) is open and the web service is running, then the application itself.
