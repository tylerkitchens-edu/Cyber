Lesson 3: Security Zones and Identity Management

Level 4: Cybersecurity Essentials

Lesson Overview

Building on the network security architecture foundations from Level 3 — where you learned about firewalls, ACLs, DMZ design, IDS/IPS placement, and defense-in-depth — this lesson focuses on how organizations define and manage security zones and control who gets access to what. You will explore the purpose and design of intranets, extranets, honeynets, and ad hoc networks, then dive deep into identity and access management (IAM), which is one of the most critical and frequently tested areas in cybersecurity.

Learning Objectives

  • Identify and explain the purpose of security zones including intranet, extranet, DMZ, honeynet, and ad hoc networks.
  • Compare security controls and access models across different zone types.
  • Explain identity and access management (IAM) principles including authentication, authorization, and accounting (AAA).
  • Differentiate between access control models: RBAC, ABAC, MAC, and DAC.
  • Describe multi-factor authentication (MFA) categories and implementation strategies.
  • Understand directory services, single sign-on (SSO), and privileged access management (PAM).

Security Zones In-Depth

In Level 3 you learned that security zones segment networks based on trust levels, with firewalls enforcing boundaries between them. Here we examine the specific zone types and their operational roles within an organization.

Intranet — Internal Private Network

A private network accessible only to an organization's internal users. Used for internal collaboration, hosting proprietary applications, and protecting sensitive workflows.

  • Access: Corporate LAN or VPN only. Authentication via Active Directory/LDAP with MFA.
  • Security: Protected by segmentation, VLANs, firewalls, and SIEM monitoring.
  • Examples: HR portals, internal wikis, ticketing systems, payroll applications.
// Example flow
Employee → Corporate LAN / VPN → Intranet server (HR portal, wiki, ticketing)

Extranet — Controlled External Access

A controlled extension of the intranet that gives authorized external parties (partners, vendors, customers) limited and audited access to specific internal resources.

  • Access: Authenticated and authorized via SSO, MFA, client certificates, or site-to-site VPN.
  • Security: Sits behind reverse proxies and WAFs. Strict logging, encryption, and least-privilege controls are mandatory.
  • Examples: Vendor dashboards, partner portals, B2B API endpoints.
// Example flow
Partner → Secure Portal / VPN → Extranet server → Controlled access to specific internal resources

Honeynet

A controlled network environment designed to attract and analyze attacker activity without compromising production systems. Honeynets contain multiple honeypots (decoy systems) that mimic real services. Security teams monitor attacker behavior, tools, and techniques to improve defenses and gather threat intelligence.

  • Purpose: Threat intelligence gathering, attacker technique analysis, early warning detection.
  • Placement: Isolated from production networks with strict egress controls to prevent attackers from pivoting.
  • Risk: Must be carefully managed — a compromised honeynet could become a launchpad if not properly contained.

Ad Hoc Networks

Temporary, decentralized networks that allow direct device-to-device communication without a traditional access point or router. Common in field operations, emergency response, and IoT deployments.

  • Security concern: No centralized authentication or encryption by default. Vulnerable to eavesdropping, MitM attacks, and rogue nodes.
  • Mitigation: Use encrypted protocols, device authentication, and limit ad hoc connections via group policy where possible.

Identity and Access Management (IAM)

IAM is the discipline of ensuring the right individuals access the right resources at the right times for the right reasons. It encompasses the processes, policies, and technologies used to manage digital identities and control access across an organization. IAM is built on the AAA framework:

  • Authentication: Verifying that a user or device is who they claim to be (proving identity).
  • Authorization: Determining what an authenticated user is allowed to do (enforcing permissions).
  • Accounting: Logging and tracking user activities for audit, compliance, and forensic purposes.

Multi-Factor Authentication (MFA)

MFA requires users to present two or more verification factors from different categories before granting access. The three standard factor categories are:

Factor CategoryDescriptionExamples
Something you knowKnowledge-based credentialsPasswords, PINs, security questions
Something you havePhysical tokens or devicesSmart cards, hardware tokens (YubiKey), authenticator apps, SMS codes
Something you areBiometric identifiersFingerprint, facial recognition, iris scan, voice recognition

True MFA requires factors from different categories. A password plus a security question is two knowledge factors — not MFA. A password plus a hardware token (knowledge + possession) is genuine MFA.

Access Control Models

Access control models define how permissions are assigned and enforced across systems:

  • Role-Based Access Control (RBAC): Permissions are assigned to roles (e.g., "Network Admin," "Help Desk Technician"), and users are assigned to roles. This simplifies management in organizations with clearly defined job functions.
  • Attribute-Based Access Control (ABAC): Access decisions are based on attributes of the user, the resource, and the environment (e.g., department, clearance level, time of day, device type). More flexible than RBAC but more complex to implement.
  • Mandatory Access Control (MAC): Access is determined by classification labels (e.g., Top Secret, Secret, Confidential) assigned by a central authority. Users cannot change access permissions. Common in military and government environments.
  • Discretionary Access Control (DAC): Resource owners control who has access to their resources. Common in Windows file permissions (owner grants read/write to others). Flexible but less secure since users can modify permissions.

Directory Services and SSO

Directory services (such as Microsoft Active Directory or LDAP) provide a centralized database of user accounts, groups, policies, and authentication credentials. They enable administrators to manage access across the entire organization from a single source of truth.

Single Sign-On (SSO) allows users to authenticate once and gain access to multiple systems without re-entering credentials. SSO improves user experience and reduces password fatigue, but creates a single point of compromise — if the SSO credential is stolen, the attacker gains access to all connected systems. SSO is typically implemented using protocols like SAML, OAuth 2.0, or OpenID Connect.

Privileged Access Management (PAM)

PAM controls and monitors access for accounts with elevated privileges — administrator accounts, service accounts, root access, and domain admin credentials. PAM solutions typically include:

  • Credential vaulting: Storing privileged credentials in an encrypted vault rather than in plaintext or memory.
  • Session recording: Logging all privileged sessions for audit and forensic review.
  • Just-in-time access: Granting elevated privileges only when needed and automatically revoking them after a defined period.
  • Least privilege enforcement: Ensuring privileged users only have the minimum permissions necessary for their specific task.

The Principle of Least Privilege

Every user, process, and system should operate with the minimum level of access necessary to perform its function. This limits the blast radius of compromised accounts and reduces insider threat risk. Least privilege should be enforced at every layer: user accounts, service accounts, API keys, firewall rules, and database permissions.
