Lesson 8: Vulnerability Management

Level 4: Cybersecurity Essentials

Lesson Overview

Vulnerability management is the continuous process of identifying, classifying, prioritizing, remediating, and mitigating security weaknesses across an organization's systems and applications. In Lesson 4 you learned about the types of cybersecurity threats; this lesson focuses on the proactive side — finding and fixing the weaknesses those threats exploit before an attacker does. This is one of the most operationally important areas in cybersecurity and a core domain on both the Security+ and CySA+ exams.

Learning Objectives

  • Describe the vulnerability management lifecycle and its role in organizational security.
  • Explain CVE identifiers and CVSS scoring, and use them to prioritize remediation efforts.
  • Identify common vulnerability scanning tools and differentiate between credentialed and non-credentialed scans.
  • Understand patch management processes including testing, deployment, and rollback procedures.
  • Apply risk-based prioritization to vulnerability remediation decisions.
  • Describe compliance scanning and its relationship to regulatory frameworks.

The Vulnerability Management Lifecycle

Vulnerability management is not a one-time activity — it is a continuous cycle that adapts as new vulnerabilities are discovered and systems change. The lifecycle consists of five phases:

  1. Discovery: Inventory all assets in the environment — servers, workstations, network devices, cloud instances, containers, IoT devices. You cannot protect what you do not know exists. Asset discovery tools and configuration management databases (CMDBs) support this phase.
  2. Assessment: Scan discovered assets for known vulnerabilities using automated scanning tools. Identify misconfigurations, missing patches, default credentials, and outdated software versions.
  3. Prioritization: Rank vulnerabilities based on severity (CVSS score), exploitability (is there a known exploit in the wild?), asset criticality (is this a database server with PII or an isolated test machine?), and business context.
  4. Remediation: Apply fixes through patching, configuration changes, compensating controls, or system isolation. Not all vulnerabilities can be patched immediately — sometimes compensating controls (such as WAF rules or network segmentation) reduce risk while a permanent fix is developed.
  5. Verification and Reporting: Re-scan to confirm remediation was successful. Generate reports for stakeholders, compliance auditors, and management. Track metrics like mean time to remediate (MTTR) and vulnerability aging.

CVE and CVSS

Common Vulnerabilities and Exposures (CVE)

CVE is a standardized naming system for publicly known cybersecurity vulnerabilities. Each vulnerability receives a unique identifier in the format CVE-YYYY-NNNNN (year and sequence number). The CVE system is maintained by MITRE Corporation and funded by the U.S. Department of Homeland Security. CVE entries provide a common language that allows security teams, vendors, and tools to reference the same vulnerability unambiguously.

Example: CVE-2021-44228 (Log4Shell)
  - Affected: Apache Log4j 2.x library
  - Impact: Remote code execution via crafted log messages
  - CVSS: 10.0 (Critical)
  - Exploited in the wild within hours of disclosure

Common Vulnerability Scoring System (CVSS)

CVSS provides a numerical score (0.0–10.0) that represents the severity of a vulnerability. The score is calculated from multiple metric groups:

CVSS Score RangeSeverity RatingTypical Response
9.0 – 10.0CriticalImmediate patching or isolation. Emergency change window.
7.0 – 8.9HighPatch within days. Implement compensating controls if patch not immediately available.
4.0 – 6.9MediumPatch within standard maintenance cycle (weeks).
0.1 – 3.9LowPatch at next scheduled maintenance. Accept risk if compensating controls exist.

CVSS Base Score metrics include:

  • Attack Vector (AV): How the vulnerability is exploited — Network, Adjacent, Local, or Physical. Network-based attacks score highest because they can be exploited remotely.
  • Attack Complexity (AC): Whether special conditions must exist for the attack to succeed. Low complexity = higher score.
  • Privileges Required (PR): The level of access the attacker needs before exploitation. None = highest score.
  • User Interaction (UI): Whether the attack requires action from a user (e.g., clicking a link). No interaction required = higher score.
  • Impact (C/I/A): The effect on Confidentiality, Integrity, and Availability. High impact in all three = maximum score.

Important: CVSS alone is not sufficient for prioritization. A CVSS 10.0 vulnerability on an isolated test server with no sensitive data is lower priority than a CVSS 7.5 vulnerability on a production database with customer PII. Always combine CVSS with asset criticality and business context.

Vulnerability Scanning

Vulnerability scanners automatically probe systems and applications for known weaknesses. They compare system configurations, software versions, and exposed services against databases of known vulnerabilities.

Scan Types

  • Non-credentialed (unauthenticated) scans: Scan targets from the outside without login credentials. Identifies externally visible vulnerabilities — open ports, exposed services, missing TLS, banner information. Simulates an external attacker's view but may miss internal vulnerabilities.
  • Credentialed (authenticated) scans: Log into the target system to perform deeper analysis — checking installed software versions, registry settings, file permissions, and patch levels. Produces significantly more accurate and comprehensive results. Requires service accounts with appropriate read access.
  • Agent-based scans: Lightweight agents installed on endpoints continuously report vulnerability status to a central console. Ideal for remote workers and cloud instances that may not be reachable by network-based scanners.

Common Vulnerability Scanning Tools

ToolTypeKey Features
NessusCommercialIndustry-leading scanner with extensive plugin library. Supports credentialed scans, compliance checks, and configuration audits.
OpenVAS (Greenbone)Open SourceCommunity-maintained scanner with regularly updated vulnerability feeds. Good for organizations with limited budgets.
QualysCloud-basedSaaS vulnerability management platform. Agent-based and network scanning. Strong compliance and cloud asset coverage.

Scan Considerations

  • Scheduling: Run scans during maintenance windows when possible — some scans can impact system performance or trigger IDS alerts.
  • False positives: Scanners may report vulnerabilities that do not actually exist due to detection limitations. Always validate critical findings before allocating remediation effort.
  • False negatives: Scanners may miss vulnerabilities, especially zero-days or custom application flaws. Scanning supplements but does not replace penetration testing and code review.
  • Scope: Define scan scope clearly — which IP ranges, which cloud accounts, which application endpoints. Scanning systems you do not own or have authorization to scan is unauthorized access.

Patch Management

Patch management is the process of acquiring, testing, and deploying software updates that fix vulnerabilities or improve functionality. It is the primary remediation mechanism for known vulnerabilities.

Patch Management Process

  1. Inventory: Maintain an accurate inventory of all software, operating systems, and firmware in the environment.
  2. Monitoring: Subscribe to vendor security advisories, CVE feeds, and threat intelligence sources to stay informed about new patches.
  3. Testing: Deploy patches to a staging or test environment first. Verify that the patch does not break functionality, introduce compatibility issues, or degrade performance.
  4. Approval: Obtain change management approval based on risk assessment and testing results.
  5. Deployment: Roll out patches to production systems using automated deployment tools (WSUS, SCCM, Ansible, cloud-native patching services). Prioritize critical systems based on vulnerability severity.
  6. Verification: Confirm patches were applied successfully through rescanning, system checks, or agent reporting.
  7. Rollback Plan: Maintain the ability to reverse patches if they cause unexpected issues. Ensure backups are current before deploying critical patches.

When Patching Isn't Possible

Sometimes patches are unavailable (zero-day), incompatible with legacy systems, or require extended testing. In these cases, apply compensating controls:

  • Network segmentation to isolate the vulnerable system.
  • WAF or IPS rules to block known exploit patterns.
  • Disabling the vulnerable feature or service if it is not business-critical.
  • Enhanced monitoring and alerting on the affected system.
  • Virtual patching through security tools that mitigate the vulnerability without modifying the underlying software.

Compliance Scanning

Compliance scanning evaluates systems against specific security standards and regulatory requirements. While vulnerability scanning looks for known weaknesses, compliance scanning checks whether configurations meet defined benchmarks:

  • CIS Benchmarks: Configuration standards for operating systems, cloud platforms, databases, and network devices published by the Center for Internet Security.
  • NIST SP 800-53: Security controls required for federal systems (covered in Lesson 5).
  • PCI DSS: Payment Card Industry requirements for organizations handling credit card data.
  • HIPAA: Health Insurance Portability and Accountability Act requirements for protecting health information.
  • STIG: Security Technical Implementation Guides published by DISA for DoD systems.

Many vulnerability scanning tools (Nessus, Qualys) include compliance scanning modules that can check systems against these benchmarks automatically and generate audit-ready reports.
