Lesson 6: Secure Cloud Network Architecture

CompTIA Security+ (SY0-801)

Overview

Most organizations now run at least part of their systems in the cloud. The cloud changes who is responsible for what, and new ways of building systems bring new risks.

You will learn:

  • cloud deployment models (public, private, hybrid, community) and multicloud;
  • the shared responsibility model: what the provider secures and what you secure;
  • serverless, microservices and infrastructure as code (IaC);
  • cloud-delivered security (Security Service Edge) and the trade-offs between architectures.

On the exam this is mostly objectives 3.1 (cloud architecture models and their trade-offs) and 3.2 (Security Service Edge).

Step 3: Key ideas to remember

Deployment models

ModelWhat it is
PublicShared infrastructure run by a provider (AWS, Azure, Google Cloud)
PrivateCloud infrastructure used by one organization only
HybridA mix of on-premises or private and public cloud, connected
CommunityShared by organizations with common needs (for example, government agencies)
MulticloudUsing more than one provider, for resilience or to avoid lock-in, at the cost of complexity

Shared responsibility

The provider always secures the physical data centers and hardware. The more the provider manages, the less you do: with infrastructure as a service (IaaS) you patch the operating system; with software as a service (SaaS) you mostly manage users, permissions and data. You are always responsible for your data and who can access it. Most cloud breaches are customer misconfigurations, such as a storage bucket left public.

New ways of building, new risks

  • Serverless: you upload code and the provider runs it. No servers to patch, but each function's permissions must be tight.
  • Microservices: an application split into many small services that talk over APIs. Each API is something more to secure.
  • Infrastructure as code (IaC): networks and servers defined in files and built automatically. Every build is consistent and reviewable, but one mistake in a template is copied everywhere.
  • Security Service Edge (SSE): security delivered from the cloud (secure web gateway, cloud access security broker, Zero Trust network access), so remote users are protected wherever they are.

Weighing an architecture

Security+ asks you to compare options on availability, resilience, ease of recovery, cost, scalability, who is responsible, and data sovereignty: data stored in another country is subject to that country's laws.

Check your understanding

A company uses software as a service (SaaS) for email. Which is still the company's responsibility?

In SaaS the provider runs everything below the application; the customer still owns its data, users and permissions.

A team builds all its cloud networks from template files kept in version control. What is this?

IaC makes builds repeatable and reviewable. It also means a mistake in the template spreads to every build.

Customer records stored with a cloud provider in another country become subject to that country's laws. What is this concern called?

Data sovereignty: where data physically lives decides which laws apply to it.
