Lesson 8: Explain Vulnerability Management

CompTIA Security+ (SY0-801)

Overview

New vulnerabilities are published every day. Vulnerability management is the repeating cycle of finding them on your systems, deciding which matter most, fixing them and proving they are fixed.

You will learn:

  • the kinds of vulnerabilities: unpatched and unsupported systems, misconfigurations, code flaws, zero-days, shadow IT and more;
  • how vulnerabilities are found: scanning, cloud posture tools, code review and penetration tests;
  • prioritizing with CVSS, CVE and context, and reading a scan report;
  • remediation, verification, reporting, bug bounties and responsible disclosure.

On the exam this is mostly objectives 2.4 (types of vulnerabilities and attack surfaces) and 4.3 (vulnerability management tasks).

Step 3: Key ideas to remember

Where vulnerabilities come from

KindExample
Unpatched, unsupported or obsolete systemsAn old Windows server that no longer gets updates
MisconfigurationDefault passwords, open ports, a public storage bucket
Code flawsHardcoded secrets, unsafe error handling, race conditions (time-of-check to time-of-use)
Zero-dayA flaw attackers use before a patch exists
Unmanaged thingsStale credentials, rogue devices, shadow IT (systems IT doesn't know about), code in public repositories
Newer surfacesLarge language models (LLMs), identity providers, mobile and wireless devices, virtualization

Finding them

  • Vulnerability scanners compare systems against a database of known flaws. A credentialed scan signs in and sees far more than one that doesn't.
  • IP address management (IPAM) helps find devices you didn't know about; cloud security posture management (CSPM) checks cloud settings; source code review finds flaws before release; penetration test reports show what an attacker could actually exploit.
  • A false positive is a reported flaw that isn't really there; a false negative is a real flaw the scan missed, which is the more dangerous of the two.

Prioritizing and fixing

  1. Prioritize: start with the CVSS score, then adjust for context: Is the system exposed to the internet? Is the flaw being exploited right now? How important is the system?
  2. Remediate: patch, change the configuration, or apply a compensating control (segmentation, a WAF) if a patch isn't possible. Some risks are formally accepted (with an exception) instead.
  3. Verify: rescan to prove the fix worked.
  4. Report: internally to management, and externally through bug bounty programs and responsible disclosure policies, which tell outside researchers how to report what they find.

Check your understanding

A scanner reports a critical flaw, but the analyst confirms the software version listed isn't actually installed. What is this?

A false positive is reported but not real. A false negative (a real flaw that wasn't reported) is more dangerous.

Two flaws both score CVSS 8.1. One is on an internet-facing web server and is being exploited in the wild. Which should be fixed first?

Same score, different context. Exposure and active exploitation raise the real priority.

After a patch is applied, what step proves the vulnerability is gone?

Verification, usually a rescan, confirms the remediation worked before the item is closed.
