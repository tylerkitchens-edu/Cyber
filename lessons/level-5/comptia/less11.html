Lesson 11: Enhance Application Security Capabilities

CompTIA Security+ (SY0-801)

Overview

Many attacks go straight for the applications an organization builds or runs, especially web apps. This lesson covers the common attacks and the coding and testing practices that stop them.

You will learn:

  • application attacks: injection, buffer overflow, cross-site request forgery, directory traversal, privilege escalation and replay;
  • secure coding: input validation, secure cookies, safe error handling and keeping secrets out of code;
  • testing: static code analysis, secrets scanning in repositories and code signing;
  • DevSecOps: building security into automated pipelines (CI/CD).

On the exam this is mostly objectives 4.1 (application security and repositories), 2.5 (application attacks) and 2.4 (code vulnerabilities).

Common application attacks

AttackWhat happensMain defence
Injection (SQL, command)Input is run as code or as a database queryInput validation and parameterized queries
Buffer overflowToo much data overwrites memory next to it, sometimes letting the attacker run codeMemory-safe languages, bounds checking
Forgery (CSRF)A malicious page makes your browser send a request to a site you're signed in toAnti-CSRF tokens, SameSite cookies
Directory traversal"../../" in a filename reaches files outside the web folderValidate and restrict file paths
ReplayA captured valid request or token is sent againTimestamps, one-time tokens, encryption
Privilege escalationA normal user gains admin rights through a flawLeast privilege, patching

Secure coding basics

  • Validate all input on the server: type, length, format. Never trust the browser.
  • Secure cookies: the Secure flag (HTTPS only), HttpOnly (scripts can't read it), SameSite (not sent with requests from other sites).
  • Show users generic error messages; keep the details in logs. Unsafe exception handling leaks information.
  • Never hardcode passwords or API keys. Keep them in a secrets vault, and run secrets scanning on code repositories to catch any that slip in.

Testing and trust

  • Static code analysis reads the source code without running it, early in development.
  • Code signing proves software came from the publisher and hasn't been changed since. It protects against malicious updates.
  • In a CI/CD pipeline these checks run automatically on every change, so security doesn't slow releases down. This is DevSecOps.

Check your understanding

A login form passes whatever the user types straight into a database query. Which attack does this allow, and what fixes it?

Parameterized queries keep user input as data, so it can never change the query.

A developer accidentally commits a cloud API key to a public code repository. Which control would have caught it?

Secrets scanning checks repositories for keys and passwords. The key should also be revoked and replaced at once.

Which cookie setting stops JavaScript on the page from reading the session cookie?

HttpOnly limits the damage of cross-site scripting. Secure makes it HTTPS only; SameSite helps against CSRF.
