Lesson 5: Secure Enterprise Network Architecture

CompTIA Security+ (SY0-801)

Overview

Where you put a device and what it is allowed to talk to matters as much as how it is configured. This lesson covers designing an on-premises network so that one compromise doesn't spread everywhere.

You will learn:

  • security zones, segmentation (logical and physical) and air-gapped networks;
  • device placement and attack surface, and how a device should fail (open or closed);
  • secure remote access: VPNs, tunneling, out-of-band management and secure file transfer;
  • Zero Trust architecture in practice: checking the user, the device's health and the application every time.

On the exam this is mostly objectives 3.1 (architecture models: on-premises, segmentation, air gaps) and 3.2 (managing the security architecture).

Step 3: Key ideas to remember

Zones and segmentation

  • Split the network into security zones by trust level: the internet, a screened subnet (DMZ) for public servers, the internal user network, and a restricted zone for the most sensitive systems.
  • Logical segmentation (VLANs, firewall rules) separates zones on shared hardware. Physical segmentation uses separate hardware. An air-gapped network has no connection to other networks at all.
  • Segmentation limits lateral movement: an attacker on a guest laptop should not be able to reach the payroll server.

Placement, attack surface and failure modes

  • Put each control where it sees the traffic it must inspect, for example a firewall between every pair of zones.
  • The attack surface is everything an attacker could reach. Turn off unused ports and services to shrink it.
  • Fail-closed (fail-secure) blocks everything when a device fails: safer, but it causes an outage. Fail-open lets everything through: traffic keeps flowing, but unprotected. The right choice depends on whether availability or security matters more for that link.
  • Diversity: using different vendors at different layers means one vendor's flaw doesn't defeat every layer.

Zero Trust in practice

Zero Trust replaces "inside the network means trusted" with a check on every request: Is the user authenticated (with MFA)? Is the device known, in the inventory and healthy (patched, with endpoint protection running)? Is this user allowed to use this application right now? Only then is access granted, to that one application.

Check your understanding

A company wants its public web server reachable from the internet but kept away from the internal network. Where should it go?

A screened subnet sits between the internet and the internal network, with firewall rules on both sides.

A firewall protecting a hospital's patient records fails. The design blocks all traffic until it is fixed. What is this?

Fail-closed (fail-secure) favours security over availability.

Under Zero Trust, a signed-in employee's laptop is missing three months of patches. What should happen?

Zero Trust checks the device as well as the user. An unhealthy device doesn't get access, whatever network it is on.
