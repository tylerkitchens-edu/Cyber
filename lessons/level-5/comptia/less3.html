Lesson 3: Explain Cryptographic Solutions

CompTIA Security+ (SY0-801)

Overview

Cryptography is how data stays secret and trustworthy, both stored and in transit. You met the basics in Level 4; Security+ expects you to pick the right tool for a situation.

You will learn:

  • symmetric and asymmetric encryption, key exchange and key length;
  • hashing, salting and digital signatures;
  • public key infrastructure (PKI): certificates, certificate authorities, revocation (CRL and OCSP), wildcard and self-signed certificates;
  • where encryption is applied: full disk, partition, volume, file, database, record and in transit.

On the exam this is mostly objective 1.3 (appropriate cryptographic solutions).

Symmetric, asymmetric and hashing

How it worksUsed forExamples
SymmetricOne shared key locks and unlocksFast bulk encryptionAES
AsymmetricA public key and a private key; what one locks, only the other unlocksKey exchange, digital signaturesRSA, elliptic curve (ECC)
HashingOne-way: data becomes a fixed-length fingerprint that can't be reversedIntegrity checks, storing passwordsSHA-256

In practice they work together: asymmetric encryption safely exchanges a symmetric key, and the symmetric key encrypts the data. That is what TLS does for every HTTPS website. Longer keys are harder to break.

Salting and signatures

  • Salting adds a random value to each password before hashing, so two people with the same password get different hashes and precomputed cracking tables don't work.
  • A digital signature is a hash encrypted with the sender's private key. Anyone can check it with the sender's public key. It proves integrity and who sent it (non-repudiation).
  • Obfuscation (hiding, for example steganography or tokenization) makes data harder to understand without being encryption.

PKI and certificates

  • A certificate binds a public key to a name (a website, a person). A certificate authority (CA) signs it; browsers trust it because they trust the CA's root.
  • To get one, you generate a key pair and send a certificate signing request (CSR) to the CA.
  • A wildcard certificate (*.example.com) covers every subdomain. A self-signed certificate is fine for internal testing but isn't trusted by others.
  • A stolen or compromised certificate is revoked: listed on a certificate revocation list (CRL), or checked live with OCSP.
  • Key escrow keeps a copy of keys with a trusted party so data can be recovered.

Where to encrypt

A stolen laptop needs full disk encryption. One sensitive column in a database needs record or database-level encryption. Data moving across a network needs transport encryption (TLS, a VPN).

Check your understanding

Two users choose the same password, but their stored hashes are different. What explains this?

A unique random salt per user changes the hash, which also defeats precomputed rainbow tables.

A company wants one certificate to cover shop.example.com, mail.example.com and www.example.com. What should it request?

*.example.com covers every subdomain of example.com.

Which key does a sender use to create a digital signature?

Only the sender has the private key, so only they could have made the signature. Anyone checks it with the sender's public key.
